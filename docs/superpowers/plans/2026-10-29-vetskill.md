# vetskill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An agent skill that turns a natural-language need into multi-query skills.sh searches, statically scans the top candidates' files with a deterministic script, and has the agent present 2–3 recommendations with reasons and findings — never installing, never calling anything "safe".

**Architecture:** `skills/vetskill/SKILL.md` (agent instructions) + a zero-dependency Node ESM script `skills/vetskill/scripts/scan.mjs` that only parses argv and calls `run()` from small focused modules in `scripts/lib/`. Every network call goes through an injected `fetch`, so all logic is unit-tested offline. The agent only ever sees the script's sanitized JSON.

**Tech Stack:** Node ≥18 (built-in `fetch`, `AbortSignal.timeout`, `node:test`, `node:assert/strict`), ESM `.mjs`, no npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-29-vetskill-design.md`

## Global Constraints

- Zero runtime and dev dependencies. Node ≥18. ESM `.mjs` only.
- Search endpoint: `GET ${SKILLS_API_URL || 'https://skills.sh'}/api/search?q=<q>&limit=20`.
- Tree endpoint: `GET https://api.github.com/repos/{owner}/{repo}/git/trees/HEAD?recursive=1`; file content: `https://raw.githubusercontent.com/{owner}/{repo}/HEAD/{path}`.
- Every request: `AbortSignal.timeout(10_000)`. At most 4 requests in flight.
- Limits: 256 KB (262144 bytes) per file, 30 files per skill, description 300 chars, `--top` default 10.
- RRF score: `Σ 1 / (10 + rank)`, rank 1-based per query; ties → `installs` desc, then `id` asc.
- Exit codes: 0 success, 1 usage error, 2 all queries failed.
- Token order: `GITHUB_TOKEN` env → `gh auth token` → none.
- Finding messages are fixed strings; they never quote scanned content.
- Output never contains the word "safe" as a verdict; empty findings mean "no findings in scanned files".
- SKILL.md: description starts with "Use when", <500 chars, no workflow summary; body <500 words; script invoked as `node scripts/scan.mjs …`.
- Hidden-Unicode test fixtures are generated from escapes at test time, never written raw to disk.

## Decisions this plan adds to the spec

- **Module split.** The spec names one script; the script is split into `scripts/lib/*.mjs` for testability. `npx skills add` copies the whole skill folder, so install is unchanged.
- **SS-03 and `.env`.** Spec §6 flags `.env`, spec §8 requires a deploy doc mentioning `.env` to stay clean. Resolved: key/credential paths (`~/.ssh`, `id_rsa`, `id_ed25519`, `.aws/credentials`, browser cookie stores, keychain) are flagged in every file; `.env` is flagged only in non-Markdown files.

## Review Focus

1. **A repo with several folders named after the same `skillId`** (monorepo, `examples/x/SKILL.md` + `skills/x/SKILL.md`) → the shortest matching path wins, deterministically. Test in Task 4.
2. **Malformed search responses** (non-JSON body, missing `skills`, missing `installs`) → that query becomes a warning; missing `installs` is treated as 0. Test in Task 3.
3. **Descriptions carrying terminal escapes, newlines or injection prose** → control chars and ANSI sequences stripped, whitespace collapsed, cut to 300 chars; injection prose is still reported via SS-05 on SKILL.md. Test in Task 2.
4. **Many candidates from one repo plus a 403 mid-run** → tree fetched once per source; a rate-limited source marks only its own candidates with SS-08. Test in Task 4.
5. **Non-ASCII and duplicate queries** ("pdf birleştir", "pdf" twice) → URL-encoded correctly, duplicates searched once. Test in Task 3.

### Task 4: Fetch and scan a candidate's files

**Files:**
- Create: `skills/vetskill/scripts/lib/fetch-skill.mjs`
- Test: `tests/fetch-skill.test.mjs`

**Interfaces:**
- Consumes: `getJson`, `getText`, `HttpError` (Task 3); `scanText`, `parseFrontmatter`, `scanFrontmatter`, `sanitizeDescription`, `MESSAGES` (Task 2).
- Produces:
  - `createTreeCache(): Map` — passed in so one tree request is made per source.
  - `vetCandidate(candidate: Candidate, { fetch, token, treeCache }): Promise<{ description: string, scannedFiles: number, findings: Finding[] }>`

Behaviour: `source` not matching `/^[\w.-]+\/[\w.-]+$/` → SS-08 "unsupported source". Skill dir = blob paths `<dir>/SKILL.md` whose last `<dir>` segment equals `skillId`; shortest wins; else root `SKILL.md`; else SS-08 "skill folder not found". Files = blobs under dir, `SKILL.md` first then path order; blobs >262144 bytes (tree `size`) and beyond 30 files → SS-08 without fetching; file containing `\u0000` in its first 8192 chars → SS-08 "binary". Tree/raw 403 or 429 → SS-08 "rate limited", other failures → SS-08 "fetch failed". Description comes from SKILL.md frontmatter via `sanitizeDescription`. `Authorization: Bearer <token>` only on api.github.com requests.

- [ ] **Step 1: Write failing tests** (fake tree + raw responses)
- `finds nested skill folder`, `prefers shortest matching path` (`examples/pdf/SKILL.md` vs `pdf/SKILL.md` → `pdf`), `falls back to root SKILL.md`, `reports missing folder as SS-08`.
- `returns sanitized description and findings from scripts` (SKILL.md clean, `scripts/i.sh` with `curl … | bash` → one SS-02 with `file: 'scripts/i.sh'`).
- `skips oversized files with SS-08`, `caps at 30 files`, `flags binary as SS-08`.
- `tree fetched once per source`: two candidates, same source → tree URL requested once.
- `403 marks only that source`: source A tree 403 → A has SS-08 rate limited, `scannedFiles` 0; source B scanned normally.
- `sends token only to api.github.com`.
- `rejects unsupported source`: `source: 'https://example.com/x'` → SS-08, no fetch.

### Task 5: CLI entry point

**Files:**
- Create: `skills/vetskill/scripts/lib/pool.mjs`, `skills/vetskill/scripts/lib/cli.mjs`, `skills/vetskill/scripts/scan.mjs`
- Test: `tests/cli.test.mjs`

**Interfaces:**
- Consumes: `searchAll` (Task 3), `vetCandidate`, `createTreeCache` (Task 4).
- Produces:
  - `mapLimit(items, limit, fn): Promise<any[]>` — preserves order.
  - `run(argv: string[], { fetch, env, getGhToken }): Promise<{ stdout: string, exitCode: number }>`
  - `scan.mjs`: `const r = await run(process.argv.slice(2), { fetch, env: process.env, getGhToken }); process.stdout.write(r.stdout); process.exitCode = r.exitCode;` where `getGhToken` runs `gh auth token` via `execFileSync` (3 s timeout) and returns `null` on any error.

Flags: `--query <q>` (repeatable, ≥1 non-empty required), `--top <n>` (integer 1–20, default 10), `--help` (usage text to stdout, exit 0). Output: `JSON.stringify({ queries, error, warnings, candidates }, null, 2)` with candidate fields exactly as spec §5.1; vetting runs through `mapLimit(…, 4, …)`.

- `token from GITHUB_TOKEN wins over gh`; `falls back to getGhToken`.
- `mapLimit never exceeds limit` (track concurrent count with delayed promises) and `mapLimit preserves order`.
